# 11 · 系统日志分析

从侧栏打开 **系统日志分析**，选择最近 1、7、30 或 90 天以及 100、300 或 1000 条上限，点击 **读取并分析**。功能只读取本机 Windows `System` 日志中的主要启停和故障事件，不修改系统、服务或审计配置，也不是完整的事件查看器。

## 记录与解读

| 记录来源与 ID | 说明 |
| --- | --- |
| Kernel-General 12 / 13 | 系统启动 / 正在关闭 |
| EventLog 6005 / 6006 / 6009 | 日志服务启动、停止及启动附近的版本信息；不应直接等同于完整开关机次数 |
| User32 1074 | 进程或用户发起的关机/重启请求，可展开原始字段核对进程、用户、原因与注释 |
| Kernel-Power 41 / EventLog 6008 | 未正常关机后的记录，不能单独确定故障原因 |
| WER-SystemErrorReporting / BugCheck 1001 | 停止错误报告，结合停止代码与转储文件调查 |
| WHEA、disk、Ntfs、storahci、stornvme、storport | 硬件、磁盘或存储相关线索 |
| volmgr 46 / 161 | 转储初始化或写入问题 |
| Service Control Manager 7031 / 7034 | 服务意外终止 |
| WindowsUpdateClient 19 | 更新安装线索，时间接近不证明它导致重启 |
| Eventlog 104 / Kernel-General 1 | 日志清除或时间调整，可能影响证据完整性和时间顺序 |

程序同时匹配来源和 ID，不依赖本地化后的事件消息来分类。顶部统计是**记录条数，不是重启次数**；同一故障可能同时产生 41、6008、1001。

事件 41 表示此前没有正常关闭，但可能涉及断电、系统卡死、停止错误或 VPS 宿主机重置。`BugcheckCode=0` 或缺少转储并不能排除停止错误。6008 的写入时间通常在随后启动时，不能直接当作故障发生时刻。解读依据见 [微软异常重启排查](https://learn.microsoft.com/en-us/troubleshoot/windows-server/performance/troubleshoot-unexpected-reboots-system-event-logs)和[事件 41 的含义与局限](https://learn.microsoft.com/en-us/troubleshoot/windows-client/performance/event-id-41-restart)。

## 如何排查异常重启

1. 筛选 **异常关机记录** 或 **停止错误**，按时间查看目标记录。
2. 点击 **查看详情**，核对事件原文、结构化字段、停止代码和转储路径。
3. 参考前后十分钟的关联记录，检查关机请求、更新、服务、WHEA、存储和转储失败线索。这是时间关联，不是因果结论；密集多次重启、时钟调整或日志缺失会影响判断。
4. 有转储时使用 WinDbg 分析；没有转储时检查转储配置、分页文件、磁盘空间及 volmgr 事件。
5. VPS 同时核对服务商维护、宿主机、监控和控制台记录，本机日志无法证明云平台发生了什么。

所有列表和关联时间统一显示 UTC。原文中的时间可能按系统语言/时区显示，请核对后再关联。日志清除、未启用、权限不足或读取失败会提示；达到上限时应缩小范围或提高上限。读取失败会保留上次成功结果，并明确标示其不是本次结果。

## 导出与容量

**导出诊断报告** 保存当前读取结果及分析为 JSON，包含原文、XML、结构化字段与采集范围。它导出整次读取结果，不受当前搜索或分类过滤影响。报告可能含主机名、账户、文件路径或注释，分享前请核对。

单条消息最多显示 8192 个字符，XML 最多 32768 个字符，超长时标示截断。关联记录最多 16 条，读取最多 1000 条；导出不是完整 `.evtx` 备份。需要完整原始证据时使用 Windows 事件查看器另行保存。

界面默认目标为 1320×840 逻辑像素，并按当前工作区和 DPI 缩小；低分辨率远程桌面保留可访问的滚动区域。表格可横向滚动，详情抽屉支持查看完整说明。
