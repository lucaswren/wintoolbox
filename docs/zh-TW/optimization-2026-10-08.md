# 四階段優化交付記錄

## 已落實

1. 可靠性：Update/Defender備份逐項檢查寫入，恢復前驗證所需字段；損壞備份拒絕恢復。防火牆、ping、系統更新、時間、Defender探測保留未知態。寫操作無論成功失敗都復查原模塊。自更新增加受限暫存目錄、復制前後哈希校驗、舊exe備份、替換失敗日志和啟動失敗回滾。
2. 狀態與並發：增加模塊狀態API；重疊慢查詢合並；支持取消的查詢傳遞共享context，最後一個調用者退出時取消命令；其他原生查詢保持單個後臺任務。系統命令並發上限6，後端按帳戶/網路/時間等資源序列化寫操作。Windows Update恢復以原設定為目標；Defender明確以啟用為目標。系統管理員組用固定SID解析，並通過NetAPI查詢和修改成員；更新服務狀態使用注冊表，任務狀態使用COM接口。
3. 工程規范：由Go導出方法與JSON DTO生成橋接類型契約，前端API進行類型檢查；增加ESLint、Prettier、故障回歸測試及Windows CI。拆出更新器、快照、共享查詢、日志和模塊狀態邏輯；useAction/useActions改為actionRunner/useSystemActions。構建使用npm ci，鎖檔案版本同步，產物統一放artifacts/releases。開發環境與文件對齊。
4. UI與發布體驗：帳戶分為使用者管理/安全策略；KeepAlive保留草稿；按鈕允許換行、側欄可滾動；避免單項操作後的全局遮罩；修正鎖定狀態顏色和ping文案；顯示狀態採集時間。日志最多500條，帶模塊與級別顏色，支持展開、自動滾動和導出。自更新有下載量/速率/取消及自動下載偏好。電源操作明確提示強制關閉應用。修復依賴審計報告的Vue和source-map-js漏洞。

## 驗證

- Go：11個回歸測試，覆蓋備份寫入失敗、損壞備份、未知狀態、查詢合並/取消、下載狀態讀取/取消清理、摘要匹配、預發布版本與更新器啟動失敗回滾；全部通過。
- 前端：6個回歸測試通過；lint、橋接類型檢查、生成契約一致性檢查、格式檢查通過。
- Go靜態分析與gofmt檢查通過；git diff --check通過。
- 模擬UI：十個頁面，960×600和1120×720，草稿保留，無頁面錯誤及主區域橫向溢出。截圖位于artifacts/ui。
- npm audit：最終鎖檔案0項已報告漏洞。
- 完整Windows桌面構建通過，exe與SHA256位于artifacts/releases。
- 構建仍有第三方VueUse的兩條PURE注釋警告，不影響構建結果。

本次未執行真實系統設置寫操作、真實自更新安裝或跨Windows版本/高DPI驗收。介面測試使用模擬Wails後端；更新器故障測試僅替換臨時目錄中的測試檔案。真實部署前按[開發規范](development.md)中的虛擬機清單驗收。橋接層有類型檢查，Vue頁面仍為JavaScript。資源鎖保護當前進程，不替代多實例之間的系統協調。

四階段優化首次交付時保持 1.2.0，僅生成本地構建。後續按使用者要求將版本重新設為 1.0.0，更新請求及文件統一指向 lucaswren/wintoolbox，並在備份後刪除、重建線上公開倉庫，再發布 v1.0.0。舊版 1.2.0 使用者需手動安裝。
